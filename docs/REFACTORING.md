# 核心状态与存储重构

## 行为与职责

- 草稿输入的文字、选择区和输入法组合状态由 ViewModel 持有，Compose 只渲染与上报输入。移除页面中的第二份文本以及 `draftReset` / `draftResetExpectedText` 同步补偿。
- `StateWriter` 对写入和读取屏障排序。工作流在点击时取得队列中的输入快照；后续输入不会混入本次任务。读取失败禁止写入默认空状态，自动保存失败会阻止依赖它的操作，允许明确重试。
- `Draft.revision` 表示内容/标签的编辑版本。用户修改后再改回相同文字，仍属于新草稿；旧工作流不会清掉它。编辑器的界面版本还保护尚未写入磁盘的输入。
- `RunWorkflow` 负责步骤执行，固定本次 AI 配置，返回结构化结果。全部步骤成功后一次提交记录和对应版本的草稿变更，提示文案由表现层负责。
- 网络操作属于创建它们的数据环境。切换演示/真实数据前取消并等待旧环境任务，完成已有编辑保存后再切换，防止旧任务把结果写入新环境。

- 对话输入仅在用户消息成功持久化后清除，写盘失败保留输入并退出忙碌状态；网络流回调沿用任务生命周期，取消后不再修改新环境的界面。

## 持久化和兼容性

- `LocalRepository` 只协调状态、串行更新和环境选择。
- `SnapshotStore` 将记录、草稿、配置及加密后的 API 密钥作为一个原子快照写入；磁盘写入失败不发布新内存状态，也不会提前替换独立凭据。
- `SnapshotMigrations` 明确升级旧的默认工作流并立即持久化升级结果；`JsonCodec` 只做数据映射。用户删除的预设不会在重启时重新出现。
- 原有 `state.json` / `demo-state.json`、工作流 ID、记录及草稿保持可读取；缺少草稿版本时使用 0，旧偏好设置中的加密密钥迁移到快照。真实与演示数据仍分开存储。
- `ConfigurationCodec` 继续使用 iOS schemaVersion 1 的交换格式，不向用户导入的工作流额外添加预设。
- `NoteArchive` 处理 Markdown/ZIP。文件名同秒冲突时只加后缀，不修改正文中的创建时间；保留原有去重和大小限制。

## 验证范围

新增回归覆盖：编辑后改回原文、同一工作流固定配置、写入屏障和失败恢复、读盘失败不覆盖原数据、旧凭据迁移、写盘失败后的凭据一致性、ZIP 同秒记录日期保留、切换环境取消旧任务。

原 `CaptureUiTest` 的保存和清除恢复场景已合并到 `DefaultWorkflowUiTest`，统一使用独立测试包与同一套启动、键盘布局及窗口焦点同步机制。AI 测试使用本地 HTTP 服务，不验证真实模型输出质量。实际执行结果见 [本次回归日志](refactor-tests.txt)。
